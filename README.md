# مستندات پروژه تحلیل شبکه اجتماعی

در این پروژه، شبکه اجتماعی به‌صورت یک گراف بدون‌جهت و بدون‌وزن در نظر گرفته شده است. هر کاربر یک رأس و هر رابطه دوستی یک یال است.

## نمادهای مورد استفاده

- `V`: تعداد کاربران یا رأس‌های گراف 
- `E`: تعداد روابط دوستی یا یال‌های گراف 
- `deg(u)`: تعداد دوستان کاربر `u` 
- `Δ`: بیشترین درجه یک رأس در گراف 
- `R`: تعداد نامزدهای پیشنهاد دوستی 
- `M`: تعداد دوستان مشترک دو کاربر 
- `S`: مجموع درجه دوستان مستقیم کاربر در الگوریتم پیشنهاد دوست 
- `K`: تعداد کاربران اولیه انتخاب‌شده برای انتشار خبر 
- `C(V,K)`: تعداد حالت‌های انتخاب `K` کاربر از میان `V` کاربر


---

## 1. ساختار اصلی گراف

شبکه به‌صورت فهرست مجاورت پیاده‌سازی شده است.

```cpp
std::unordered_map<std::string, User> users;

std::unordered_map<
    std::string,
    std::unordered_set<std::string>
> adjacency;
```

ساختار `users` اطلاعات هر کاربر را بر اساس شناسه او نگهداری می‌کند.

ساختار `adjacency` برای هر کاربر مجموعه‌ای از شناسه دوستان او را ذخیره می‌کند. استفاده از `unordered_set` مانع ثبت تکراری یک دوست می‌شود.

چون گراف بدون‌جهت است، رابطه بین دو کاربر در هر دو مجموعه دوستان ثبت می‌شود.

جست‌وجوی یک کاربر در حالت متوسط `O(1)` زمان می‌برد.

بررسی وجود یک رابطه دوستی نیز در حالت متوسط `O(1)` زمان نیاز دارد.

پیچیدگی فضایی کل گراف `O(V + E)` است.

استفاده از فهرست مجاورت برای شبکه اجتماعی مناسب است؛ زیرا چنین گراف‌هایی معمولاً تنک هستند و نسبت به ماتریس مجاورت با فضای `O(V²)` حافظه کمتری مصرف می‌کنند.

## 2. افزودن، حذف و ویرایش کاربران و روابط

### 2.1 افزودن کاربر

ابتدا خالی نبودن شناسه و نام و تکراری نبودن شناسه بررسی می‌شود. سپس اطلاعات کاربر در `users` و یک مجموعه دوستان خالی در `adjacency` قرار می‌گیرد.

ساختمان داده‌های استفاده‌شده:

- `unordered_map`
- `unordered_set`

پیچیدگی زمانی : `O(1)`

پیچیدگی فضایی اضافی :`O(1)` 

### 2.2 حذف کاربر

ابتدا یک کپی از مجموعه دوستان کاربر ساخته می‌شود. سپس شناسه کاربر از مجموعه دوستان تمام همسایه‌های او حذف و در پایان خود کاربر از `users` و `adjacency` پاک می‌شود.

ساختمان داده‌های استفاده‌شده:

- `unordered_map`
- `unordered_set`
- یک کپی موقت از مجموعه دوستان

اگر کاربر `u` دارای `deg(u)` دوست باشد، پیچیدگی زمانی : `O(deg(u))`

پیچیدگی فضایی : `O(deg(u))` 
زیرا مجموعه دوستان کاربر هنگام حذف کپی می‌شود.

### 2.3 ویرایش کاربر

کاربر با استفاده از شناسه در `unordered_map` پیدا می‌شود و نام او تغییر می‌کند.

ساختمان داده استفاده‌شده:

- `unordered_map`

پیچیدگی زمانی : `O(1)`

پیچیدگی فضایی : `O(1)`

### 2.4 افزودن رابطه دوستی

ابتدا وجود هر دو کاربر، متفاوت بودن شناسه‌ها و تکراری نبودن رابطه بررسی می‌شود. سپس شناسه هر کاربر در مجموعه دوستان کاربر دیگر درج می‌شود.

ساختمان داده‌های استفاده‌شده:

- `unordered_map`
- `unordered_set`

پیچیدگی زمانی : `O(1)`

پیچیدگی فضایی : `O(1)`

### 2.5 حذف رابطه دوستی

رابطه از مجموعه دوستان هر دو کاربر حذف می‌شود تا بدون‌جهت بودن گراف حفظ شود.

ساختمان داده استفاده‌شده:

- `unordered_set`

پیچیدگی زمانی : `O(1)`

پیچیدگی فضایی : `O(1)`

## 3. لیست کردن دوستان یک کاربر

ابتدا مجموعه دوستان کاربر از فهرست مجاورت دریافت می‌شود. سپس شناسه دوستان در یک `vector` کپی و مرتب می‌شوند تا ترتیب خروجی ثابت باشد.

ساختمان داده‌های استفاده‌شده:

- `unordered_set` برای نگهداری دوستان
- `vector<string>` برای ساخت خروجی
- الگوریتم `sort` برای مرتب‌سازی

اگر تعداد دوستان کاربر `deg(u)` باشد، کپی‌کردن شناسه‌ها `O(deg(u))` و مرتب‌سازی آن‌ها `O(deg(u) log deg(u))` زمان می‌برد.

در نتیجه پیچیدگی زمانی کل : `O(deg(u) log deg(u))`

پیچیدگی فضایی اضافی : `O(deg(u))`

---

## 4. بررسی ارتباط دو کاربر

برای بررسی وجود مسیر بین دو کاربر از الگوریتم BFS استفاده شده است. جست‌وجو از کاربر مبدأ شروع می‌شود و تمام کاربران قابل‌دسترسی را به‌ترتیب سطح بررسی می‌کند.

ساختمان داده‌های استفاده‌شده:

- `queue<string>` برای صف BFS
- `unordered_map<string, int>` برای فاصله و وضعیت بازدید
- `unordered_map<string, string>` برای والد رأس‌ها

هر رأس حداکثر یک بار وارد صف می‌شود و هر رابطه دوستی نیز در طول پیمایش بررسی می‌شود.

پیچیدگی زمانی : `O(V + E)`

پیچیدگی فضایی اضافی : `O(V)`

---

## 5. پیدا کردن کوتاه‌ترین مسیر بین دو کاربر

چون گراف بدون وزن است، BFS کوتاه‌ترین مسیر را بر اساس تعداد یال‌ها پیدا می‌کند.

هنگام کشف هر رأس، والد آن ذخیره می‌شود. پس از رسیدن به مقصد، مسیر با دنبال‌کردن والدها از مقصد به مبدأ ساخته و سپس معکوس می‌شود.

ساختمان داده‌های استفاده‌شده:

- `queue<string>` برای BFS
- `unordered_map<string, int>` برای فاصله
- `unordered_map<string, string>` برای والد رأس‌ها
- `vector<string>` برای مسیر نهایی

اجرای BFS دارای پیچیدگی زمانی `O(V + E)` است. بازسازی مسیر نیز در بدترین حالت `O(V)` زمان می‌برد؛ بنابراین پیچیدگی زمانی کل : `O(V + E)`

پیچیدگی فضایی : `O(V)`

---

## 6. محاسبه فاصله یک کاربر تا تمام کاربران

ابتدا یک BFS تک‌منبعی از کاربر موردنظر اجرا می‌شود. فاصله هر کاربر برابر تعداد یال‌های کوتاه‌ترین مسیر از مبدأ تا آن کاربر است.

برای کاربران غیرقابل‌دسترسی مقدار فاصله `-1` در هسته نگهداری و در خروجی JSON به شکل `null` نمایش داده می‌شود.

در پایان، نتیجه بر اساس فاصله و سپس شناسه کاربر مرتب می‌شود. کاربران غیرقابل‌دسترسی در انتهای خروجی قرار می‌گیرند.

ساختمان داده‌های استفاده‌شده:

- `queue<string>` برای BFS
- `unordered_map<string, int>` برای فاصله‌ها
- `vector<DistanceEntry>` برای خروجی
- الگوریتم `sort`

اجرای BFS `O(V + E)` زمان می‌برد.

ساخت خروجی `O(V)` و مرتب‌سازی آن `O(V log V)` زمان نیاز دارد.

در نتیجه پیچیدگی زمانی کل : `O(V + E + V log V)` 
که می‌توان آن را به‌صورت `O(E + V log V)` نیز نوشت.

پیچیدگی فضایی : `O(V)`

## 7. بخش اختیاری: بهینه‌سازی انتشار خبر

برای ارزیابی یک مجموعه از کاربران اولیه، از BFS چندمنبعی استفاده شده است. تمام کاربران اولیه با فاصله صفر وارد صف می‌شوند و خبر به‌صورت لایه‌به‌لایه در شبکه منتشر می‌شود.

مجموعه‌های انتخابی با این معیارها مقایسه می‌شوند:

1. خبر به بیشترین تعداد کاربر برسد.
2. تعداد روزهای انتشار کمتر باشد.
3. مجموع فاصله کاربران تا کاربران اولیه کمتر باشد.
4. اگر نتایج برابر باشند، ترتیب شناسه‌ها برای انتخاب خروجی ثابت استفاده شود.

پیاده‌سازی دارای دو حالت دقیق و حریصانه است.

### 7.1 حالت دقیق

شناسه تمام کاربران ابتدا مرتب می‌شود.

اگر تعداد ترکیب‌های انتخاب `K` کاربر حداکثر `2,000,000` باشد، تمام ترکیب‌های ممکن تولید و ارزیابی می‌شوند.

برای ارزیابی هر ترکیب، یک BFS چندمنبعی با پیچیدگی `O(V + E)` اجرا می‌شود.

ساختمان داده‌های استفاده‌شده:

- `vector<string>` برای شناسه کاربران و کاربران انتخاب‌شده
- `queue<string>` برای BFS چندمنبعی
- `unordered_map<string, int>` برای فاصله
- Recursion برای تولید ترکیب‌ها

با در نظر گرفتن تولید ترکیب‌ها، BFS و مقایسه مجموعه‌های انتخابی، پیچیدگی زمانی به شکل زیر است:

```text
O(V log V + C(V,K) × (V + E + K))
```

در نمایش ساده‌تر، زمانی که هزینه BFS غالب باشد، می‌توان آن را به شکل زیر نوشت:

```text
O(V log V + C(V,K) × (V + E))
```

پیچیدگی فضایی : `O(V + K)`

### 7.2 حالت حریصانه

اگر تعداد ترکیب‌ها بیشتر از `2,000,000` باشد، برنامه به حالت حریصانه می‌رود.

در هر مرحله، تمام کاربران انتخاب‌نشده بررسی می‌شوند. هر نامزد موقتاً به مجموعه اضافه و با BFS چندمنبعی ارزیابی می‌شود. سپس بهترین نامزد به مجموعه نهایی اضافه می‌شود.

پیچیدگی زمانی تقریبی :

```text
O(V log V + K × V × (V + E + K log K))
```

پیچیدگی فضایی : `O(V + K)`

حالت حریصانه برای جلوگیری از رشد بسیار زیاد تعداد ترکیب‌ها استفاده شده است و برخلاف حالت دقیق، تضمین نمی‌کند که در همه شبکه‌های بزرگ بهترین جواب ریاضی پیدا شود.

## 8. پیدا کردن گروه‌های مختلف شبکه

گروه‌های مختلف شبکه همان مؤلفه‌های هم‌بند گراف هستند.

ابتدا شناسه کاربران مرتب می‌شود. سپس برای هر کاربر بازدیدنشده یک BFS اجرا می‌شود و تمام کاربران قابل‌دسترسی از آن در یک گروه قرار می‌گیرند.

در این بخش، همسایه‌های هر رأس و اعضای هر مؤلفه نیز برای تولید خروجی ثابت مرتب می‌شوند.

ساختمان داده‌های استفاده‌شده:

- `queue<string>` برای BFS
- `unordered_set<string>` برای کاربران بازدیدشده
- `vector<string>` برای شناسه‌ها و همسایه‌ها
- `vector<vector<string>>` برای مؤلفه‌ها
- الگوریتم `sort`

هزینه استاندارد پیدا کردن مؤلفه‌ها بدون مرتب‌سازی `O(V + E)` است.

با در نظر گرفتن مرتب‌سازی شناسه کاربران، اعضای مؤلفه‌ها و همسایه‌ها، پیچیدگی زمانی پیاده‌سازی فعلی :

```text
O(V log V + E log Δ)
```

پیچیدگی فضایی : `O(V)`

## 9. محاسبه آمار شبکه

در این بخش اطلاعات زیر محاسبه می‌شوند:

- تعداد کل کاربران
- تعداد کل روابط دوستی
- میانگین تعداد دوستان
- اندازه و اعضای بزرگ‌ترین مؤلفه
- کاربر دارای بیشترین تعداد دوست

تعداد روابط از مجموع درجه کاربران تقسیم بر دو به دست می‌آید.

میانگین تعداد دوستان از رابطه `2E / V` محاسبه می‌شود.

بزرگ‌ترین گروه با الگوریتم مؤلفه‌های هم‌بند پیدا می‌شود.

برای پیدا کردن کاربر دارای بیشترین دوست نیز درجه تمام کاربران محاسبه و مرتب می‌شود.

ساختمان داده‌های استفاده‌شده:

- فهرست مجاورت
- `vector<vector<string>>` برای مؤلفه‌ها
- `vector<DegreeEntry>` برای درجه کاربران
- الگوریتم BFS
- الگوریتم `sort`

پیچیدگی زمانی پیاده‌سازی فعلی :

```text
O(V log V + E log Δ)
```

پیچیدگی فضایی : `O(V)`

## 10. پیدا کردن کاربران دارای بیشترین تعداد دوست

درجه هر کاربر از اندازه مجموعه دوستان او به دست می‌آید.

تمام کاربران در یک `vector` قرار می‌گیرند و ابتدا بر اساس تعداد دوستان به‌صورت نزولی و در صورت برابر بودن بر اساس شناسه به‌صورت صعودی مرتب می‌شوند.

سپس فقط کاربرانی که درجه آن‌ها برابر بیشترین درجه شبکه است برگردانده می‌شوند.

ساختمان داده‌های استفاده‌شده:

- فهرست مجاورت
- `vector<DegreeEntry>`
- الگوریتم `sort`
- الگوریتم `remove_if`

پیچیدگی زمانی : `O(V log V)`

پیچیدگی فضایی : `O(V)`

## 11. پیدا کردن دوستان مشترک دو کاربر

برای کاهش تعداد بررسی‌ها، مجموعه دوستان کوچک‌تر پیمایش می‌شود و هر شناسه در مجموعه دوستان بزرگ‌تر جست‌وجو می‌شود.

دوستان مشترک در یک `vector` قرار می‌گیرند و برای ثابت بودن ترتیب خروجی مرتب می‌شوند.

ساختمان داده‌های استفاده‌شده:

- دو `unordered_set<string>`
- `vector<string>`
- الگوریتم `sort`

اگر تعداد دوستان مشترک `M` باشد، پیچیدگی زمانی :

```text
O(min(deg(a), deg(b)) + M log M)
```

پیچیدگی فضایی : `O(M)`

## 12. بخش اختیاری: پیدا کردن افراد کلیدی و پل‌های ارتباطی

برای پیدا کردن کاربران کلیدی از مرکزیت بینابینی و الگوریتم Brandes استفاده شده است.

برای هر کاربر به‌عنوان مبدأ:

1. یک BFS اجرا می‌شود.
2. فاصله‌ها و تعداد کوتاه‌ترین مسیرها محاسبه می‌شوند.
3. پیشینیان هر رأس ذخیره می‌شوند.
4. رأس‌ها به‌ترتیب معکوس پردازش می‌شوند.
5. سهم هر رأس در کوتاه‌ترین مسیرها به امتیاز آن اضافه می‌شود.

چون گراف بدون‌جهت است، امتیاز نهایی بر دو تقسیم می‌شود.

در خروجی کاربران کلیدی، کاربرانی برگردانده می‌شوند که بالاترین امتیاز غیرصفر را داشته باشند.

ساختمان داده‌های استفاده‌شده:

- `queue<string>` برای BFS
- `stack<string>` برای پردازش معکوس
- `unordered_map<string, int>` برای فاصله
- `unordered_map<string, double>` برای تعداد مسیرها و وابستگی‌ها
- `unordered_map<string, vector<string>>` برای پیشینیان
- `vector<CentralityEntry>` برای نتیجه

پیچیدگی استاندارد Brandes در گراف بدون وزن:

```text
O(V(V + E))
```

در پیاده‌سازی فعلی، همسایه‌های هر رأس در هر اجرای BFS مرتب می‌شوند. با در نظر گرفتن این مرتب‌سازی، پیچیدگی زمانی دقیق‌تر :

```text
O(V(V + E log Δ))
```

پیچیدگی فضایی : `O(V + E)`

## 13. پیشنهاد دوست

برای پیشنهاد دوست از روش دوستانِ دوستان استفاده شده است.

ابتدا دوستان مستقیم کاربر پیمایش می‌شوند. سپس دوستان هر دوست به‌عنوان نامزد پیشنهاد بررسی می‌شوند.

خود کاربر و دوستان فعلی از نامزدها حذف می‌شوند.

تعداد دوستان مشترک هر نامزد به‌عنوان امتیاز او نگهداری می‌شود و نتیجه بر اساس امتیاز نزولی و سپس شناسه صعودی مرتب می‌شود.

ساختمان داده‌های استفاده‌شده:

- `unordered_set<string>` برای دوستان فعلی
- `unordered_map<string, int>` برای امتیاز نامزدها
- `vector<FriendSuggestion>` برای خروجی
- الگوریتم `sort`

اگر `S` مجموع درجه دوستان مستقیم کاربر و `R` تعداد نامزدهای نهایی باشد، پیچیدگی زمانی :

```text
O(S + R log R)
```

پیچیدگی فضایی : `O(R)`

## 14. بخش اختیاری: تشخیص گروه‌های دوستی پیشرفته

برای تشخیص جامعه‌ها از الگوریتم Girvan–Newman استفاده شده است.

مراحل کلی الگوریتم:

1. یک نسخه کاری از گراف ساخته می‌شود.
2. مرکزیت بینابینی تمام یال‌ها محاسبه می‌شود.
3. یال دارای بیشترین مرکزیت حذف می‌شود.
4. مؤلفه‌های هم‌بند جدید پیدا می‌شوند.
5. مقدار Modularity تقسیم‌بندی محاسبه می‌شود.
6. بهترین تقسیم‌بندی مشاهده‌شده نگهداری می‌شود.
7. این روند تا حذف تمام یال‌ها ادامه پیدا می‌کند.

در صورت برابر بودن امتیاز چند یال، ترتیب شناسه‌ها برای انتخاب نتیجه ثابت استفاده می‌شود.

ساختمان داده‌های استفاده‌شده:

- `map<string, set<string>>` برای گراف کاری
- `map<pair<string, string>, double>` برای مرکزیت یال‌ها
- `queue<string>` برای BFS
- `stack<string>` برای پردازش معکوس
- `map<string, vector<string>>` برای پیشینیان
- `vector<vector<string>>` برای جامعه‌ها
- `set<string>` برای اعضای هر جامعه

در بدترین حالت، یک یال در هر مرحله حذف می‌شود و مرکزیت یال‌ها دوباره محاسبه می‌شود.

با در نظر گرفتن استفاده از `map` و `set`، کران زمانی پیاده‌سازی به شکل زیر بیان می‌شود:

```text
O(V × E × (V + E) × log(V + E))
```

برای الگوریتم استاندارد Girvan–Newman در گراف متصل، فرم رایج و ساده‌شده معمولاً حدود زیر در نظر گرفته می‌شود:

```text
O(VE²)
```

پیچیدگی فضایی : `O(V + E)`

## نحوه کامپایل و اجرای پروژه

### پیش‌نیازها

برای اجرای پروژه موارد زیر لازم است:

- کامپایلر سازگار با C++17 مانند `g++`
- Python 3
- کتابخانه Flask برای رابط کاربری

تمام دستورها باید از پوشه اصلی پروژه، یعنی پوشه‌ای که فایل `main.cpp` در آن قرار دارد، اجرا شوند.

### کامپایل هسته در Windows

در PowerShell یا Command Prompt دارای `g++` اجرا کنید:

```powershell
g++ -std=c++17 -O2 -Wall -Wextra -I./Core -I./Analytics -I./Recommendation -I./search main.cpp Core/Graph.cpp Analytics/search.cpp Analytics/InfluenceMaximization.cpp Recommendation/FriendRecommendation.cpp Recommendation/CommunityDetection.cpp search/algorithms.cpp -o main.exe
```

بعد از اجرای دستور، فایل `main.exe` در ریشه پروژه ساخته می‌شود.

### کامپایل هسته در Linux

```bash
g++ -std=c++17 -O2 -Wall -Wextra -I./Core -I./Analytics -I./Recommendation -I./search main.cpp Core/Graph.cpp Analytics/search.cpp Analytics/InfluenceMaximization.cpp Recommendation/FriendRecommendation.cpp Recommendation/CommunityDetection.cpp search/algorithms.cpp -o main
```

### اجرای مستقیم هسته در Windows

نمونه چند فرمان:

```powershell
.\main.exe addUser A "Ali"
.\main.exe addUser B "Reza"
.\main.exe addFriendship A B
.\main.exe getFriends A
.\main.exe shortestPath A B
.\main.exe networkStatistics
```

### اجرای مستقیم هسته در Linux

```bash
./main networkStatistics
```

اطلاعات کاربران و روابط به‌صورت پیش‌فرض در فایل `network.json` واقع در ریشه پروژه ذخیره می‌شوند.

### اجرای رابط کاربری وب

ابتدا هسته C++ را کامپایل کنید. سپس وابستگی Python را نصب کنید:

```bash
python -m pip install -r Ui/requirements.txt
```

برنامه Flask را از ریشه پروژه اجرا کنید:

```bash
python Ui/app.py
```

بعد از اجرا، آدرس زیر را در مرورگر باز کنید:

```text
http://127.0.0.1:5000
```

رابط کاربری از طریق قرارداد خط فرمان، فایل اجرایی C++ را اجرا می‌کند و خروجی JSON را در صفحات وب نمایش می‌دهد.
